# OpenFit

An independent, open-source Android starter for a simple watch companion. OpenFit is not affiliated with Noise or NoiseFit and does not contain their code, branding, assets, or services.

## Current scope

- Dark, high-contrast dashboard with Home, Health, Devices, Sleep and Settings tabs.
- The Health tab is built with Jetpack Compose on Material 3 (`material3` 1.4.0): heart card, LOW/HIGH/SAMPLES stat tiles and a short data note, in the same monochrome/red/monospace language as the rest of the app. Home, Sleep and Settings use the same Compose treatment; Devices keeps its Views UI because it hosts the interactive BLE lists. The card names the source of a reading (watch history or live) and uses the watch's own five-minute sample count.
- Permission-aware Bluetooth LE discovery for recognizable Noise / ColorFit names, saved-watch reconnect, and a connect-first GATT flow: the app now connects directly, retries transient failures (for example GATT 133), and starts Android system bonding only when the watch reports that the link needs authentication or encryption. A watch with a saved binding answers its own bind inquiry before the protobuf probe, so a reconnect pairs in about a second instead of waiting out the SE probe.
- Pairing QR scanner accepts QR content containing a Bluetooth MAC address; proprietary NoiseFit QR payloads are not decoded.
- Live heart rate when a connected device exposes the Bluetooth SIG Heart Rate Service (0x180D) and a notifiable Heart Rate Measurement characteristic (0x2A37). On the ZhBracelet path the watch's daily heart-rate history (key `0x0D`) is decoded and shown on connect; the Buzz refuses the vendor's one-shot measurement command and does not stream a live value. Notification-write outcomes are reflected in the connection state.
- Read-only GATT diagnostics list discovered service/characteristic UUIDs and properties, plus an on-device connection log and a pairing log (both with a Copy button) so a failed physical test can be reported without adb.
- On a Noise watch exposing `16186f00`, the app negotiates MTU 247 and speaks the SE ("Apricot") chunked-protobuf account exchange. Two pairing outcomes are supported and chosen at runtime. A **ColorFit Ultra Buzz** answers the SE account group with `NOT_SUPPORT`, so it binds through the vendor's ZhBracelet ("NavPlus") channel on service `00000001` (`00000002` write / `00000003` notify); the key-108 request was answered with `result=1` and the watch left pairing mode. A **Noise Watch Beat** answers the SE probes instead (binding status, then a bind check carrying its name, MAC and firmware), so the app completes the SE `bind_result`; that continuation still needs a hardware retest.
- Latest heart rate plus local daily min/max and minute-sample summary. On a ZhBracelet watch the latest value comes from the watch's own five-minute history, not from continuous monitoring.
- **Watch settings over ZhBracelet:** a Settings tab shows battery and firmware, clock sync, find watch, do-not-disturb, bright screen, continuous HR, the sedentary reminder with its time window, the alarm list, and battery saver. Writes are optimistic and sent one at a time with a 5 s reply watchdog; a refusal or silence restores the previous value. Device info is refreshed on connect, and the stored sedentary/alarm values are read on demand. "Forget watch" clears the local binding and token only; the watch keeps its own pairing.
- Editable manual sleep-duration entry in 15-minute increments, stored locally.
- On-device crash capture: the last uncaught exception (including a QR scanner failure) is shown in the diagnostics report, so bugs can be reported without adb.
- No account, analytics, network permission, or cloud sync.

Static inspection of NoiseFit 5.5.0's supplied XAPK found a main APK and ARM64 split, the `libVeryFitMulti.so` and `libble-crypto.so` libraries, plus `com.zhapp.ble.BerryBluetoothService` methods/logs showing bond-state checks and Android `createBond()` before connecting. OpenFit keeps that bonding path as a fallback instead of a precondition, so a watch that accepts a plain BLE connection is no longer blocked by a failed or hanging system pairing prompt. A later decompilation pass recovered the watch's Berry GATT profile, SPP frame layout, ack frame, protobuf envelope and bind commands (see `PROTOCOL.md`). On 2026-11-17 a physical ColorFit Ultra Buzz on Android 16 was confirmed to expose the `16186f00` service, connect, and accept notification setup for all five characteristics. A write attempt showed that the service answers the Berry frame with the SE "busy" control frame `00 00 01 02 00 00`, so a further pass recovered the SE ("Apricot") chunked-protobuf transport and its `SEFunctionId` account bind. The on-device build confirmed the transport (ready/received control frames at MTU 247) and exposed that the vendor ships two different `SEWear` schemas; the bind now uses the BLE one. Independent implementations of both layers, plus the ZhBracelet bind, clock sync and user-info encoders, live in `app/src/main/java/com/openfit/app/protocol/` and are covered by unit tests. On the 2026-11-18 device runs the watch answered both SE account probes with `SEWear{id=16|17, error_code=NOT_SUPPORT}`, so the SE transport and envelope are correct but this firmware does not implement the account bind there; the second run also bonded the watch but found no RFCOMM listener for the classic SPP socket. NoiseFit has a second Berry bearer for exactly this case — the same private cmd 2/3/4 account exchange carried over BLE on the `aa01` service (`Berry-Test`) — so OpenFit can use that too. The decisive finding came from the vendor's model routing: `NavPlusConnectHandler` binds this model family through the bundled `com.zjw.zhbraceletsdk`, a third stack that talks plaintext `0xAB` frames on service `00000001` (write `00000002`, notify `00000003`) with a key-108 bind request. OpenFit now subscribes to `00000003` and tries that bind (type 0, then a type-1 inquiry) before Berry, and the classic SPP path has been removed because the watch is LE-only. Two Berry defects were fixed on the way: the phone→watch and watch→phone frame magics were swapped, and inbound frames were never acknowledged. Vendor-level pairing is confirmed on the physical watch: the ZhBracelet bind returned `type=0 result=1`, the watch reached its home screen, and reconnects now answer the persisted-binding inquiry with `type=1 result=1`. After the bind the app sends the vendor's clock sync and user-info profile. The APK also contains a JNI BLE cipher (RC4 variant, decoded) for a different watch family whose opcodes remain unknown. OpenFit does not copy NoiseFit code. The QR flow accepts a Bluetooth MAC address only. Device-name filtering is a convenience, not proof of identity. A Noise Watch Beat (`00:00:00:7A:55:0F`) confirmed the second path on 2026-11-18: it exposes `16186f00`, `aa01` and an extra `000077d0` channel (no `00000001`), answered SE ids 16/17 with real data, and is now bound by continuing to id 18 instead of aborting when the reply's `device_verify` flag is clear.

## Build

Requires JDK 17+ and Android SDK platform/build tools 35, plus JDK 17 and Gradle 8.9 (AGP 8.6.1). From this directory:

    gradle --no-daemon :app:testDebugUnitTest :app:assembleDebug

Install on a test device with:

    adb install -r app/build/outputs/apk/debug/app-debug.apk

The GitHub Actions Android workflow runs unit tests and creates this debug APK for every push/PR; version tags publish it as a GitHub Release asset. Android 12+ requests Bluetooth scan/connect permission; Android 6–11 requests location permission while scanning. Location is not collected or stored.

## Health data and limitations

The current release does not estimate, infer, or import sleep stages, and does not use Health Connect. The heart-rate history is an on-device, notification-derived daily summary and cannot promise continuous coverage. A manually logged sleep duration is a journal entry, not a medical measurement. Background synchronization, Health Connect integration, live vendor heart-rate streaming, the remaining vendor settings and watch-face transfer are future work. The Settings tab already exposes the settings commands recovered from the ZhBracelet SDK; each one still needs an individual hardware check on the Buzz. The ZhBracelet path does decode the watch's daily heart-rate history, so the dashboard has a real reading on the first connection even though the Buzz refuses the vendor's on-demand measurement command. BLE connection, `16186f00` profile detection, and notification setup are validated on hardware (the watch connected while Android reported it as not bonded). The SE account bind is attempted on connect; the ColorFit Ultra Buzz answers `NOT_SUPPORT` and is bound through the ZhBracelet key-108 exchange on `00000001` (confirmed on hardware), while the Noise Watch Beat answers the SE probes and is bound there (the continuation is implemented, hardware retest pending). The classic SPP path has been removed because the watch is LE-only. QR scanning has a dependency fix that now builds, with the physical retest still pending. A failed QR launch is recorded locally and appears in the diagnostics report.
